# Input inspection

Inspected all 150 supplied files by size, SHA256 and file signature. Checked CRCs and inventoried every member of residual.jar (3,613 entries) and webcache.zip (9 entries). Full private reports are generated by tools/inspect_input.py under build/audit.

The Windows launch configuration selects com.orangepixel.residual.desktop.DesktopLauncher. The supplied Java runtime is Windows Java 17.0.12. Game startup identifies Residual 1.4.1 / libGDX 1.13.1 and sets a desktop 60 FPS cap. The original EXE, uninstallers, shortcuts, GOG metadata and Windows runtime are not used by the port.

The game JAR includes desktop Java classes, assets, Linux ARM32/ARM64 native libraries, Windows and other platform libraries. This port selects ARM64 through the runtime. The game’s supported no-controller argument avoids its controller scanner; a separate adapter replaces optional desktop social integration without modifying game data. The desktop preferences provider is subclassed to redirect all game settings/save slots to the port save folder.

Relevant startup, display, input, profile, world generation and save paths were inspected as code. Binary assets and unrelated libraries were inventoried and integrity checked, not individually reverse engineered or visually reviewed. Decompilation was used only for local private inspection; none is included in the source or BYO archive.
